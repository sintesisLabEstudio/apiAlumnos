Diagrama 4 - Modelo de datos y mapeo entre capas
[Kotlin DTOs]                         [C# Models / EF Entities]                 [SQL Server Tablas]
AlumnoDto                             Alumno                                    ALUMNOS
  - codAlumno  <------------------>     - CodAlumno  <----------------------->   - COD_ALUMNO (PK)
  - nombres    <------------------>     - Nombres    <----------------------->   - NOMBRES
  - apellidos  <------------------>     - Apellidos  <----------------------->   - APELLIDOS
AsignaturaDto / AsignaturaNueva       Asignatura                                ASIGNATURAS
  - idAsignatura <---------------->     - IdAsignatura <--------------------->   - ID_ASIGNATURA (PK, IDENTITY)
  - nomAsignatura <--------------->     - NomAsignatura <-------------------->   - NOM_ASIGNATURA (UNIQUE)
NotaDto                               Nota                                      NOTAS
  - codAlumno  <------------------>     - CodAlumno  <----------------------->   - COD_ALUMNO (FK -> ALUMNOS)
  - idAsignatura <---------------->     - IdAsignatura <--------------------->   - ID_ASIGNATURA (FK -> ASIGNATURAS)
  - nNota      <------------------>     - NNota      <----------------------->   - N_NOTA (1..3)
  - nota       <------------------>     - Valor [JsonPropertyName("nota")] <->   - NOTA (decimal(2,1))
ListadoNota (Kotlin, @SerializedName) recibe respuesta del endpoint /api/notas/listado:
  - COD_ALUMNO, NOMBRE_COMPLETO, NOM_ASIGNATURA, NOTA_1..NOTA_3, PROMEDIO (calculado en API cuando hay 3 notas).

Relacion: Un alumno puede tener muchas notas; una asignatura puede tener muchas notas; cada nota pertenece a un alumno y a una asignatura.
Notas clave de integracion
- La app Kotlin (codigoKotlin) actua como cliente: construye peticiones con Retrofit/OkHttp, serializa/deserializa JSON con Gson y ejecuta red en Dispatchers.IO.
- RetrofitClient define la URL base (http://10.0.2.2:50555/ en emulador o http://127.0.0.1:50555/ en dispositivo con adb reverse) apuntando a la API C#.
- La API C# (AlumnosApi) expone endpoints REST en Controllers, aplica validaciones/reglas de negocio y usa Entity Framework Core (AlumnosContext) para persistencia.
- SQL Server/LocalDB almacena los datos en baseDatosAlumnos (tablas ALUMNOS, ASIGNATURAS, NOTAS) segun scripts de creacion y la cadena de conexion en appsettings.
- El flujo completo es: UI Kotlin -> DTO/HTTP -> Controller C# -> EF Core -> SQL Server y la respuesta vuelve por el mismo camino en formato JSON.
